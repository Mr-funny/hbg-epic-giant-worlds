# 我把 468 条东方巨物 Prompt 的经验，拆成了三路 Agent Skill

我前后做了很多轮泰国、印度教、道教、印度尼西亚和东方仙侠的图，最后发现，最难的根本不是写出一句“史诗级、8K、PBR、体积云”。

真正难的是同时解决下面这些问题：

- 用户只输入一个国家、一个宗教或一个动作，系统怎样把它扩写成完整而可信的世界，而不是旅游元素拼贴。
- 巨物感怎样来自广角空间、人物尺度和工程关系，而不是永远把建筑顶部裁掉。
- 为什么同一批图不能每张都有一棵树、一个平台和一座远处宫殿。
- 天空、地球、月球为什么能显著增强视觉冲击，又为什么很容易把文化题材带成通用太空歌剧。
- 东方美学怎样保持稳定，但又不把泰国、印度尼西亚、印度教全部换成中国白玉天宫。
- 参考图怎样只提供材质、光线和空气感，而不把圆门、中轴线、中央人物也复制过来。
- 图生视频怎样从实际母图重新写，避免宫殿生长、神像变脸、人物放大和镜头失控。
- 漫游 Prompt 题库怎样用于学习和发现，却不直接继承原 Prompt 的风格，更不能把第三方原文当成自己的开源素材。

这篇文章把这套过程完整拆开，也解释为什么我最后没有做成一个“万能大 Prompt”，而是拆成三个互相衔接的 Agent Skill。

开源项目：<https://github.com/Mr-funny/hbg-epic-giant-worlds>

## 零、这组三路 Skill 分别做什么

| Skill | 任务 | 核心判断 |
|---|---|---|
| `hbg-keyword-giant-world` | 一个关键词扩写成通用巨物世界 | 先理解文化和空间，再扩张尺度 |
| `hbg-oriental-giant-world` | 把关键词或现有 Prompt 转成东方巨物美学 | 风格稳定，构图不锁死，地域身份不丢失 |
| `hbg-oriental-giant-roam` | 从题库抽题、学习、改写 | 题库提供问题，不提供最终风格 |

它们的关系是：

```text
关键词 ─→ 文化扩写 ─┐
                    ├─→ 东方巨物 Style Lock ─→ 母图 ─→ 基于实际图片的 Veo Prompt
题库 ─→ 语义抽取 ──┘
```

我把它们拆开，是因为三个阶段犯的错误完全不同。

关键词扩写最容易犯的是刻板印象；东方化最容易犯的是构图换皮；漫游最容易犯的是照抄来源风格。一个大 Prompt 会把这些边界混在一起，Agent 也很难判断这次到底应该保留什么、改变什么。

## 一、第一次误判：巨物感不是“看不完整”

早期我也认为，只要低机位仰拍、巨像冲出画面、人物站在脚下，巨物感就成立。

它确实有效，但连续用几次以后问题非常明显：每一张都是相同的视觉语法。换成佛像、天宫、泰国神庙或印度教神像，骨架仍然是“地面小人 + 向上仰拍 + 顶部裁切”。

后来用户给了一个很关键的纠正：

> 应该不是完整展示的问题，应该是广角构图的问题。

这句话改变了整个系统。

巨物可以完整出现。真正决定尺度的是一组关系：

```text
近处可读物体
+ 微小人物
+ 一座主巨构
+ 长引导线
+ 空气透视
+ 一个熟悉的环境或天体尺度
```

例如一座完整可见的巨门，只要它投下的阴影跨过街区、河流和人物，依然会比被裁掉一半的门更巨大。一个平视镜头，只要桥面栏杆向远处收束、人物只有几个像素、地球弧面在远处保持稳定，也能产生比单纯仰视更强的认知冲击。

所以 Skill 明确支持五类机位：

1. 贴地低机位。
2. 人眼平视。
3. 25—55 度斜俯视。
4. 保留地平线的高空鸟瞰。
5. 有选择地使用近垂直俯拍。

一组三张以上的图至少使用三类机位。巨物不再等于仰视。

## 二、真实失败：为什么每张图最后都有一棵树

最初的东方仙侠模板很稳定：古松在右边，枝叶延伸到上方，白玉平台在右下角，云海占左侧，远处是一座天宫。

单张很漂亮。连续生成时却像同一张图不断更换装饰。

用户直接指出：

> 不要总是有一棵树，太单一了。

这不是“把松树换成竹子”就能解决的问题。树只是表面，真正重复的是前景家族和构图骨架。

我最后把前景拆成六个家族：

- 建筑：门、柱、飞檐、回廊、墙洞。
- 地貌：峡谷、洞穴、悬崖、火山岩、冰壁。
- 水与天气：水面、雨幕、瀑布、浪、雾。
- 雕塑与工艺：巨型浮雕、祭器、桥、索具、栏杆。
- 开放前景：地面、阴影、沙丘、码头、空旷平台。
- 植物：树、根、花、竹叶，只在题材需要时使用。

然后把前景、机位、主体位置、引导线分开记录。相邻作品至少改变四项中的三项。

这条规则比“不要总有树”更有用，因为它阻止的不只是树重复，而是整个构图换皮。

## 三、天空、地球和月球为什么有用

继续对比参考图后，我们又发现：仅仅巨大还不够。真正有强烈反差的作品，往往把文化空间和一个人类非常熟悉的尺度锚点放在一起。

这个锚点可能是：

- 清晰的云海地平线。
- 地球弧面与大气辉光。
- 一轮异常巨大的月亮或太阳。
- 日食。
- 行星地平线。
- 大瀑布、长河或长桥跨越建筑和天体环境的边界。

为什么它们有效？

因为观众不需要解释月球有多大、地球弧面意味着什么、云层延伸到地平线有多远。熟悉的尺度一进入画面，巨构会立刻获得比较对象。

但这里也有一个很大的坑：天体一多，文化空间就消失，画面马上变成普通科幻壁纸。

所以我加了一条硬门禁：每张最多一个宇宙尺度锚点，而且必须为它保留负空间。飞船、全息界面、霓虹、多个巨大行星默认禁止。建筑、礼仪、材料和人物行为仍然必须第一眼属于这个关键词。

天空和天体负责放大尺度，不负责替代文化。

## 四、一个国家不是国旗、地标和民族服装的合集

用户最开始希望输入一个国家或宗教，系统就能扩展成视频。

这件事听起来简单，实际上很容易滑向刻板印象。例如“泰国”被扩写成金色寺庙、大象、僧侣、热带树和国旗全部堆进一张图；“印度尼西亚”变成婆罗浮屠、火山、海岛、面具和雨林拼贴；“印度教”则把多个神祇属性随意混在一起。

关键词 Skill 因此先做分类，再填八个槽位：

```text
核心精神
代表性地貌
建筑或工程语言
材料与工艺
纹样或象征
人物的安静动作
一个主巨构
时间、天气与光
```

每个槽位只选一到两个强关联元素。所有元素必须服务同一个视觉命题。

例如“印度尼西亚”可以成为：

```text
火山群岛 × 海上迁徙 × 石雕文明 × 潮汐显露的山体圣城
```

它不需要同时出现所有著名地标。火山地貌、海水、石雕、微小船只和一座主巨构已经足够构成完整世界。

关键词扩写的目标不是“我知道这个国家有哪些元素”，而是“我能否用这些元素建立一座可信、统一、可以进入的空间”。

## 五、东方化不是把所有东西换成中国天宫

当用户要求“把这些题材都变成我要的东方美学巨物风格”时，最危险的理解是：所有建筑都换成白玉飞檐，所有人物都穿汉服，所有环境都铺云海。

这样确实统一，但它会抹掉泰国、印度尼西亚、印度教和不同佛教传统的身份。

我最后把东方 Style Lock 分成两层。

第一层固定：

- 明亮、空灵、祥瑞、庄严、令人向往。
- 蓝白空气、自然体积光、暖金晨昏。
- 温润但真实的石、玉、木、铜、漆、丝、陶和地域材料。
- 微小人物、一个主巨构、大面积环境留白。
- 慢速稳定运镜、清楚的前中后景视差。
- 不默认黑暗、恐怖、末日和死黑前景。

第二层服从题材：

- 泰国保留泰式屋顶轮廓、佛塔、那伽、水系和热带环境。
- 印度尼西亚保留火山、海洋、candi 石构、岛屿与区域雕刻。
- 印度教保留图像学一致性、寺庙几何、河岸、灯火、花环和宇宙观。
- 中国神话才完整使用白玉平台、斗拱、飞檐、云纹和山海神兽。

统一的是画面的呼吸、尺度、光色、材质和运动节奏，不是统一成一个国家。

## 六、参考图只能借“皮肤”，不能借“骨架”

另一个反复出现的问题是：参考图的材质和氛围非常好，但一旦让模型“融合参考”，它会连构图一起继承。

圆形月洞门、中央轴线、中央人物、对称庭院，全部会在后面的画面里不断复现。即使主体已经换成弹琴、泰国或印度教，观众还是能看出它只是参考图换皮。

所以我在东方化 Skill 里加了参考防火墙。

允许继承：

- 清晰度和材质精度。
- 冷暖关系与色调。
- 云、雾、水、空气感。
- 电影质感和运动节奏。

默认禁止继承：

- 门的形状。
- 中央轴线。
- 对称布局。
- 人物位置。
- 树木框景。
- 庭院结构。
- 原始镜头和裁切。

适配之前必须先写一句新的构图声明，例如：

> 只保留参考图的清晰度、材质精度、灰蓝与暖金色调、真实电影质感；构图彻底更换为高位斜俯视、非对称开放全景。

这句话看似简单，却是从“风格参考”走向“构图复制”之间最重要的一道门。

## 七、生图提示词不能直接拿去做 Veo

一张图片的 Prompt 会描述大量静态内容：建筑是什么、人物穿什么、天空什么颜色、纹样有多精细。

如果原封不动交给图生视频模型，模型很容易把它理解成“在八秒内重新生成一次这个世界”。结果就是宫殿增生、栏杆融化、神像换脸、云层沸腾、人物变大。

真正的视频 Prompt 必须根据实际母图重新写，并回答四个问题：

1. 哪些东西真的出现在图里，位置在哪里？
2. 镜头只做哪一种主要运动？
3. 哪一类环境元素承担动态？
4. 哪些结构必须绝对刚性？

默认结构是：

```text
一个连续 8 秒镜头
一种主运镜
前景、中景、远景的分层视差
三到五个画面已经支持的环境小动作
一个微小人物动作
远景巨构和天体近乎不动
禁止新增、变形、复制、切镜和快速运动
```

例如前景是桥栏，镜头可以缓慢沿桥推进；栏杆产生最快视差，中景人物只走两步，远处神殿和月球保持稳定。云雾可以分层移动，但不能改变天气和昼夜。

视频的宏大感不是镜头越快越好，而是远景越稳定、空间关系越清楚，观众越能感到它真的巨大。

## 八、漫游模式为什么不能直接抽一条 Prompt 就使用

另一个任务里，我们从公开、无需登录、没有绕过访问限制的页面发现并解析 Prompt。

最终数据是：

- 发现唯一帖子 31,049 个。
- 成功解析 6,529 个。
- 完整 Prompt 去重前 2,660 条。
- 去重后 2,198 条。
- 严格满足东方元素、巨物尺度和完整场景条件的 Prompt 468 条。
- 失败 12 个，全部是 HTTP 404。

这批数据非常适合研究：它能告诉我们大家怎样写云海、天宫、地球、山体神像、微小人物、对称空间和超构建筑。

但“公开可见”不等于“可以整库复制到自己的 GitHub”。

更重要的是，用户已经明确说过：这些 Prompt 并不是最终最想要的风格。漫游是为了学习题材和奇观，不是为了让输出风格跟着每一条来源跳来跳去。

所以漫游模式被拆成三层：

```text
来源档案：原文、作者、URL、哈希，保持不变
语义核：奇观是什么、动作是什么、尺度机制是什么
HBG 适配：重新构图，统一写成东方巨物母图与视频语言
```

例如来源写的是低饱和月夜圆窗、中央人物和孤寂室内，漫游适配可以只保留“亲密室内开口收纳一个外部巨型世界”这个语义核，然后彻底改为非对称构图、雨后晨光、明亮蓝白云海和新的镜头位置。

来源仍然是来源，适配版才是新的创作。

## 九、为什么开源仓库只放 24 条题卡，不放 468 条原文

我最终在开源仓库里放的是 24 条 HBG 原创抽象题卡，例如：

- 巨门投下覆盖城市的影子。
- 月洞之外不是花园而是世界。
- 天外瀑布落入古井。
- 倒悬山城与正常海面。
- 海面下沉睡的巨塔。
- 莲台成为一片大陆。

它们描述的是视觉机制和问题，不复制第三方 Prompt 的完整表达。

仓库同时提供一个标准库脚本，支持用户把自己的本地 JSONL 题库导入。导入以后可以固定 seed、按主题筛选、保留历史、避免连续抽到相似机位。

本地题库默认不提交、不上传、不整库输出。只有当前学习需要的记录才被读取，并保留来源字段。

这样既能让 Skill 开箱即用，又不需要用第三方创作者的完整文字去填充一个公开仓库。

## 十、四镜头不是四张图，而是四种发现方式

用户后来要求：同一主题做四个视频，再拼成一个视频，而且前后景、景别和运镜都要有磅礴感。

如果只是生成四张同构图，后期再加四次慢推，成片仍然单调。

我把四镜头定义成四种不同的“发现方式”：

| 镜头 | 空间任务 | 推荐机位 | 默认运镜 |
|---|---|---|---|
| 门槛 | 第一次遭遇巨物 | 贴地低机位或局部框景 | 慢推 + 轻抬升 |
| 通路 | 进入文明内部 | 人眼平视、道路或水路 | 轴向推进或横向漂移 |
| 揭示 | 解释巨构怎样成立 | 斜俯视 | 缓慢下降或抬升 |
| 崇高 | 把文明放入天体尺度 | 高空鸟瞰或选择性俯拍 | 后退揭示或稳定下降 |

四镜头共享材质家族、色彩 DNA 和文化命题，但不共享同一个前景、天气、引导线和运动路径。

这才叫一个世界的四个章节，而不是一张图的四次变体。

## 十一、把一次审美判断变成 Skill，真正固化的是什么

这组三路 Skill 固化的不是“云海、白玉、古松、天宫”这些表面词，而是下面这些可复用判断：

- 一个关键词足够开始，但必须先分类和写视觉命题。
- 巨物可以完整展示，广角空间关系比裁切更重要。
- 人物极小，只作为尺度锚点。
- 一张图只保留一个主巨构和最多一个宇宙锚点。
- 树只是前景家族之一，不能成为默认答案。
- 多张图必须轮换机位、前景、主体位置和引导线。
- 东方化固定视觉 DNA，不抹除来源文化。
- 参考图只传递皮肤，不默认传递骨架。
- 视频 Prompt 必须从实际母图重写。
- 一种主运镜、一类环境运动、一个人物小动作。
- 建筑、神像、地貌和天体必须刚性稳定。
- 漫游题库提供问题，不提供最终风格。
- 原始 Prompt、来源和适配版必须分层保存。
- 自动检查通过不等于视觉完成，母图和最终视频仍要抽帧验收。

Skill 的价值，就是把“这一轮终于知道哪里不对”变成“下一轮默认先避开这个错误”。

## 十二、完整工作流

```text
接收一个关键词，或从题库抽取一个问题
→ 判断国家、宗教、文明、地点、动作或抽象概念
→ 提取文化、地貌、材料、行为和禁忌
→ 写一句视觉命题
→ 选择巨物尺度机制
→ 选择不重复的前景、机位、主体位置和引导线
→ 加入最多一个天空、月球、地球或行星尺度锚点
→ 套用东方巨物 Style Lock，但保留地域身份
→ 生成 16:9 母图
→ 检查构图复制、文化混搭、透视、人物、文字和重复结构
→ 根据实际母图重写 Veo / Gemini Prompt
→ 锁定巨构，只允许一种主运镜和克制环境运动
→ 生成并抽帧检查视频
→ 多镜头独立通过后再统一编码和拼接
```

这套系统并不只适合仙侠、天宫和宗教建筑。一个动作、一件器物、一个城市、一个抽象概念，都可以通过同样的方法变成巨物世界。

真正有冲击力的巨物，不是把所有东西都做大。

而是让观众先看懂一个熟悉的尺度，然后突然意识到：眼前这整个世界，远比自己刚才理解的更大。
